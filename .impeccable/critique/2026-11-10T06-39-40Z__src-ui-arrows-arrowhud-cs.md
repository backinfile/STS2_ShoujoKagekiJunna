# 箭矢 UI 与特效审查

审查基线为 `9f8f8744c55763007e9488a290572b96dbc94c54`，目标为 `src/UI/Arrows/ArrowHud.cs` 及其布局、悬停、部署、释放与战斗调用链。

## 整体判断

箭框、弓弦、指向、归零和命中构成完整的视觉链条，角色识别明确。常规数量下的结构值得保留。首要问题是实际攻击范围与目标提示不一致，其次是大量箭矢的阅读容量和连续结算节奏。

## 优先问题

### P1 群星闪耀的实际攻击范围没有同步到箭矢提示

**实机复现。** 打出 JA205「群星闪耀」后部署一支满弦射击，箭框与瞄准线仍只指向原目标。用弦声齐鸣完成箭矢后，四名敌人生命值均从 10000 降至 9975。当前 UI 漏掉其余三个实际受击目标，悬停其他敌人也不会列出这支箭矢。

`src/Combat/Arrows/ArrowCombat.Targeting.cs` 第 80–84 行仅在 AttackCommand 执行前扩展伤害目标。`src/Combat/Arrows/ArrowDeployment.cs` 第 14–22 行仍按卡牌原 TargetType 和 Play.Target 提供显示目标。HUD 的导线、目标悬停和命中特效沿用后者。

最小优化是统一查询实际攻击覆盖，让瞄准、悬停及命中特效复用。继续保留原始 Play.Target，供卡牌自身的单体附加效果使用。

### P2 密集悬停预览持续缩小，且集合变化时全量重建

**源码与算式确认。** `src/UI/Arrows/ArrowHud.Hover.cs` 第 40–55 行每次重建整个预览，第 66–81 行把全部关联箭矢放进最多三行。1920×1080 逻辑画布中，50 张卡牌会缩为每张约 99×139，100 张约 43×61。720p 实际显示再缩小为约 66×93、29×41，无法承担阅读牌效的用途。

移出目标再移入、切换目标，或一支箭矢消失后，剩余卡牌都会重新 NCard.Create。50 支对应一次创建 50 张完整卡面。重建行为已确认，瞬时耗时与卡顿程度尚未测量。

最小优化是设定可读的最小卡面尺寸和可见数量上限，超出后分页或滚动，并按 ArrowDeployment 身份复用预览卡。继续保留各物理副本的独立战斗修改。

### P2 箭矢阵列没有纵向容量保护

**源码与算式确认。** `src/UI/Arrows/ArrowHud.Layout.cs` 第 81–89 行只按横向区域增加行数，未使用 canvas.Y 限制底部。以当前常见单人站位、1920×1080、rowY=184 为例，友方单体区四列容纳 50 支时需要十三行，最后一行中心 Y=1336，超出画布。

箭矢可通过复制继续增长。向下扩张后会侵入敌人意图、角色和手牌区域，箭框矩形命中区也随之进入操作区。

最小优化是确定纵向安全范围，超过容量后汇总或分页展开。保留当前阵营分区、顺序和稳定槽位。

### P2 密集导线缺少当前查看对象的层级

**既有压力录像可见，当前源码确认。** `src/UI/Arrows/ArrowHud.Guides.cs` 第 11–40、72–75 行为每支箭矢绘制固定强度导线，群体箭矢还包括扇面、边界与逐目标连线。50 支群体箭矢压力画面形成连续网状，难以追踪某一支的目标。

最小优化是随数量降低非选中导线的强度，悬停箭矢时强化该支及其目标，悬停敌人时强化相关箭矢。关键信息通过高亮层级呈现。

### P2 连续就绪箭矢逐支累计特效等待

**调用链与算式确认。** `src/Combat/Arrows/ArrowCombat.cs` 第 56–58、73–76、147–149 行逐支 await。`src/UI/Arrows/ArrowHud.Feedback.cs` 第 102、109–110 行每支先请求 `(0.14 + 0.30) / 1.25 = 0.352` 秒等待。50 支显式请求合计 17.6 秒，另加牌效耗时。实际墙钟时间受 Cmd.Wait 游戏速度策略影响。

最小优化是为同一批次压缩后续箭矢的起手与飞行间隔，保留结算顺序及逐次命中反馈。批量场景需要单独衡量操作等待时间。

## 保留项与细节

- 风筝形箭框、卡图和群体卫星有明确的角色与单体／群体区分。
- 倒计时保持直立，归零前变色，数值变化有脉冲。
- 最少位移布局、删除后保留槽位和临界阻尼转向减少跳动。
- 720p 画面中的倒计时字号约 9.3 像素，连发倍率的逻辑字号 16 高于倒计时的 14。可以先小幅提高倒计时与底牌尺寸，并保留倍率的次级位置。位置为 `src/UI/Arrows/ArrowHud.cs` 第 209–211 行。

新玩家主要受倒计时及目标覆盖提示影响。熟练玩家在复制、群体加速和目标间快速查看时，更易遇到密集预览及等待累积。
