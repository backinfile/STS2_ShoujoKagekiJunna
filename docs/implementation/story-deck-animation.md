# 故事展示与飞入牌组动画

用户反馈：`塞牌动画呢？`

此前故事的直接入牌组与掉落检查通过，但漏了动画验收。旧调用只执行 `CardPileCmd.Add(..., Deck)`，没有为新生成的故事调用加牌预览，因而缺少展示、飞入动画和牌组计数完成通知。

## 修复

`KnowledgeProgress.WonCombat` 保留直接加入永久牌组及单张发放规则，收集本次成功加入结果后调用原生 `CardCmd.PreviewCardPileAdd`。最多5张水平展示，超过5张使用原生散开布局。仅本地玩家有成功入牌时等待3秒，让原生展示、飞行与计数完成通知结束后再进入普通掉落。

没有增加故事掉落或领取按钮。待发数量仍在结算前清空，基础/升级各发1张，两层发2张，生成故事的初始永久闪耀预算保持3/3。

## 失败基线

同一真实胜利脚本先在旧运行包上失败：`base visible story preview count`，实际0，预期1；同时记录到飞入次数0、计数完成通知0。实际永久牌组仍增加1张，证明此前的入牌组检查不能覆盖动画。

## 定向验证

测试先准备环境，再通过合法出牌正常获胜。观察器只记录原生预览成功创建、`NCardFlyVfx.Create` 的 Deck/adding 参数、飞行完成任务及 `CardPile.InvokeCardAddFinished`，不替换动画或胜利结果。

五场真实胜利共100项检查通过，包含原有数量、实际Deck去向、升级版本、独立闪耀预算、不创建故事奖励和普通奖励候选非空检查。录像关键帧核对故事牌展示、飞向右上角牌组、计数更新及随后出现普通掉落；六张散开布局另有实机截图。

Beta和Stable编译均为零警告、零错误；实机验证与录像为Beta 0.111.0、BaseLib 3.4.7、Core 1.6.0。仅执行本次动画改动所需的定向测试；此前舞台少女心得291项真实回合检查保留原运行版本证据。

沿 `story-direct-deck-tests.md` 的隔离环境启动方法，运行观察模组和已有对局。启动前把 `JUNNA_STORY_OUTPUT` 指向观察目录；脚本必须读同一目录。

```powershell
python tests/StoryDirectDeck/run-native-victory.py --port <隔离端口> --output-dir <观察目录> --record
python tests/StoryDirectDeck/run-native-victory.py --port <隔离端口> --output-dir <六层结果目录> --live-dir <观察目录> --cases six
```
