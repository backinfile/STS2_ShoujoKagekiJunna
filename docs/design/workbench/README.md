# 纯那工作台

各页签独立保存搜索、筛选和排序选择，切换页签与刷新后恢复。卡牌自然排序依次比较稀有度、基础费用、类型、编号。

工作台当前部署在 `vipcloud`，公开地址为 `https://junna.17181718.xyz/`，只读内容随远端提交更新；编辑使用独立长链接。数据、配图和历史记录由服务器持久化。本地 MCP 客户端通过 `local-save.config.json` 中的 `remoteURL`、`remoteToken` 连接同一远端服务；配置远端后，下面的启动命令返回远端地址，不启动本地服务。连接配置包含访问密钥，保持在 Git 忽略范围内。

服务源码、持久化路径和更新方式见 [云端部署](deploy/README.md)。其他工作树可直接使用主目录客户端，或仅同步这两个远端连接字段；日常编辑通过 MCP 提交条目增量。

本地开发时可移除这两个远端连接字段，再按以下方式启动本地服务：

启动本地服务：

```powershell
powershell -File docs/design/workbench/start-mcp.ps1
```

打开 `http://127.0.0.1:17842/`。Codex 的项目 MCP 配置会通过 STDIO 自动启动并连接同一个后台服务。多个客户端共享条目、历史和版本。

网页读取、保存、导入、撤销、恢复和上传配图都调用 `/mcp`。每条内容的版本由递增序号及内容摘要组成；同一条目的旧版本提交返回 `VERSION_CONFLICT`，整个批次保持原状。不同条目可独立提交。网页草稿按客户端存入 IndexedDB，冲突时可查看服务器内容、编辑合并结果或导出草稿。重试沿用原提交编号，服务重启后仍能识别已完成的请求。

Power 与遗物分别通过 `powers`、`relics` 按 UID 独立读取和提交，各条目单独计版本；持久化仍兼容原有 `meta.powers`、`meta.relics`。普通规则数据的版本单独计算。网页开始编辑、提交成功或处理冲突后，早先发出的同步响应会被丢弃，避免旧响应回退内容和版本号。

旧 `/file` 接口返回 `410 MCP_REQUIRED`。`start-local-save.ps1` 保留为兼容入口，转到 MCP 启动脚本。

知识牌编辑栏提供“删除一组”和“备用一组”，从组内任意一张牌可操作同组全部牌面。删除移入垃圾桶，备用可整组移回卡池，保留知识关系和发放数量，已删除成员保持原状；每次整组操作记录为一个事务，可一次撤销。原“删除”“移入备用”只操作当前单张牌。

常用工具：`workbench_status`、`workbench_query`、`workbench_get_entity`、`workbench_commit`、`workbench_history`、`workbench_restore`、`workbench_import_asset`、`workbench_export`。当前会话加载新工具前，可使用 `mcp-client.cjs`，它也通过 MCP 协议连接服务。

```js
const {callTool}=require('./mcp-client.cjs');
const card=await callTool('workbench_get_entity',{collection:'cards',id:'JH19'});
await callTool('workbench_commit',{
  requestId:require('node:crypto').randomUUID(),clientId:'card-review',label:'修改稍息备注',
  changes:[{collection:'cards',uid:card.uid,expectedVersion:card.version,updates:{notes:'...'}}]
});
```

源文件修改后运行 `npm run build`。必要的版本控制验证运行 `npm run test:mcp`；测试使用临时数据目录。

本地配置 `local-save.config.json` 包含连接密钥。后台日志为 `mcp.stdout.log` 和 `mcp.stderr.log`。服务仅监听本机地址。

“流派统计”以箭矢、知识、能量/高费为流派，伤害加成单列为小体系。展示当前牌面、奖励入口、触发牌、收益牌、跨流派、突破限制及实际触发∶收益比例。同一张兼具牌分别计入触发牌和收益牌；每个体系内按牌面去重，跨体系分别计数。数量、比例和钻取明细均遵循当前统计范围、“仅奖励入口”及定位筛选。完整卡池的文档参考保留在总览中。

箭矢牌及“将手牌作为5回合的箭矢打出”提供触发；加速、额外触发、复制、转型与调度等原工具效果统一归为收益。手牌转箭矢以固定5回合等待替代所选牌本次能量支付，并暂时移出常规循环，同时计入能量／高费收益。箭矢牌自身兼有收益时同时标记触发与收益。旧工具定位读取时兼容为收益，原工具推荐权重合入收益。

“流派统计”的“效果归类”逐项列出各体系的触发与收益效果，并读取当前范围内卡牌的完整基础描述作为示例。归类内容保存在各流派条目的 `effectRoles`，通过 MCP 维护；流派筛选同步筛选归类表。

卡牌列表与流派统计的定位使用触发、收益、跨流派、突破限制四个标签；包含条件同时满足，排除条件命中任意标签即隐藏。流派与关键词以按钮筛选，排序位于列表顶部。卡牌编辑的“分类与定位”集中显示卡池身份、流派多选、关键词及定位；跨流派由实际所属流派推导，触发与收益可按各流派分别编辑。隐藏的旧字段与效果关联继续保留。

每个具体效果单独显示牌面数，点击数量查看匹配卡牌。数量遵循统计范围、仅奖励入口及流派位置筛选；同一牌面在每项内去重，不同效果分别计入。匹配读取基础描述、费用、卡牌类型与当前知识关系，不重复计算升级描述；按当前牌名识别引用。`effect-statistics.js` 保存匹配规则，流派 `effectRoles.effects` 中的 `{id,text}` 关联规则与显示文本。

打包当前内容时，可先通过 `workbench_export` 把快照导出到临时文件，再运行 `node build.cjs --snapshot <快照路径>`；默认构建继续读取初始 seed。

静态只读副本：先通过 MCP `workbench_export` 导出快照，再执行 `node build-readonly.cjs <快照.json> <输出目录>`。输出 `index.html`、`assets/` 和 `manifest.json`，可交给静态 HTTP 服务。副本保留当前全部条目、配图、筛选和详情；省略编辑历史、草稿、连接密钥及 MCP 客户端。页面内容固定为导出时的版本，更新时重新导出和构建。只读适配仅用于这个独立构建，本地编辑工作台继续使用原构建。

总览未勾选“全部牌面”时，“完整卡池参考”依据 `STS2_Card_Reserch/docs/职业卡池设计要求_按五职业规律.md` 第1、2、6节与 `体系驱动卡池设计流程.md` 阶段4，按入池牌与基础牌展示文档参考范围。勾选后改为“全部牌面统计”，按入池牌及其关联牌的并集统计，同一牌面只计一次；费用、稀有度、类型、结构、体系及本体对比中的纯那数量均沿用此范围，并保留原有建议和差额列。备用与垃圾桶始终按各自范围统计；分组要素不改变整池基数。类型统计时箭矢按已有内部子类型计入攻击、技能或能力，卡牌显示仍为箭矢。`pool-reference.js` 保存来源范围与计算规则，文档范围保持原值。

卡池总览的“本体五职业对比”并列显示纯那与铁甲战士、静默猎手、故障机器人、亡灵契约师、储君的数量和占比，支持稀有度、类型、费用、升级费用的交叉分组；体系、卡位、突破限制、入池保留在纯那的“分组对比”中。默认对齐普通、罕见、稀有的入池奖励牌，各职业占比以自身奖励牌总数为基数。勾选“全部牌面”后，纯那包含知识附带牌等在用牌面，本体使用满解锁职业牌池中的全部牌面（含基础、远古，不含独立 TokenCardPool），占比以各自牌面总数为基数。

`native-card-pools.js` 是本体职业牌池的静态快照，记录提取日期与 C# 源码摘要。通过 `node docs/design/workbench/import-native-card-pools.cjs <spire-codex目录>` 从 `extraction/raw/src/Core/Models/CardPools` 与 `Cards` 重新生成，中文名来自同目录的 `data/cards.json`。费用读取构造函数，X 费依据 `HasEnergyCostX`，升级费用依据 `OnUpgrade` 中的费用调整；按不同牌面计数，排除战斗中的临时费用变化。

卡牌分类依据本体 `Core/Entities/Cards/CardRarity.cs`、`CardType.cs` 和 `localization/zhs/gameplay_ui.json`：稀有度支持基础、普通、罕见、稀有、远古（本体译作先古）、事件、衍生（Token）、状态、诅咒、任务；类型支持攻击、技能、能力、状态、诅咒、任务，并保留 Mod 的箭矢类型。`None` 是未指定值，不作为编辑选项。卡池归属 `cardPool` 支持角色、无色、事件、衍生、状态、诅咒、任务；“入池／不入池”由 `pool` 独立保存。知识关联牌分别保存稀有度与卡池，允许主牌附带诅咒等特殊分类；Token 是稀有度，可以是攻击或技能等类型。常规奖励统计仍只计普通、罕见、稀有的入池牌，特殊分类按实际数量统计。

每张卡牌独立配置关联牌列表和发放数量。关联为单向关系，多张牌可共用同一张关联牌，入池状态独立保存。取得知识牌时只读取该牌自己的列表，本次附带发放一次。编辑栏的“关联牌”可为任意卡牌添加已有牌或新牌，卡牌预览沿当前来源显示。

整组删除、备用和移回操作只处理当前入口及独有成员。被其他在用入口引用的共享牌，以及拥有独立入口或入池身份的牌，保留各自状态。
