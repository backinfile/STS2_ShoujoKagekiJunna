## Brief task plan

1. 复用原版 128 和 512 支飞矢的实测基线。
2. 保留每支飞矢的画面与悬停，减少逐帧牌面状态计算，并对等待态箭身批绘。

## Result and changes

已有后台记录显示最新纯那对局为测试版 v0.113.1、进阶 10、第 49 层通关。遥测缺少每场飞矢峰值和帧时间，性能对比复用同版本隔离战斗的原版基线。

- 场上达到 16 支时，等待态箭身合成到共享纹理图集，通过 `MultiMeshInstance2D` 批量绘制。每支箭保留自己的位置、角度、倒计时、引导线和悬停区域。入场与射出沿用现有动画。
- 图集每帧最多新增 4 张纹理，等待期间使用原有箭身绘制。倒计时闪光随使用创建。
- 高密度下复用布局分组。成员、目标、倒计时、重放、升级或等待期间受击次数变化时重算，其他状态变化通过 150 ms 刷新捕获。完整全局修正按当前可见牌面读取。

同一战斗、完整特效档，每组采集 360 帧。全场绘制调用包含游戏场景及其他界面。

| 飞矢数量 | HUD 平均耗时，原版 → 批绘 | 场景平均帧耗时 | 全场平均绘制调用 |
| --- | ---: | ---: | ---: |
| 128 | 4.49 → 0.46 ms | 16.67 → 16.66 ms | 1,596 → 约 1,345 |
| 512 | 55.07 → 1.95 ms | 61.21 → 16.66 ms | 5,436 → 4,413 |

- 512 支场景确认有 512 个箭身批绘实例、512 个独立悬停区域，HUD 每帧分配从约 26.49 MB 降到 0.44 MB。目标、引导线和切换特效档位的断言通过。
- 32 支不同状态飞矢可逐支悬停和翻页。16 支全特效射出后，部署数及图标节点均归零。
- 实机正常打出「星群」，两种飞矢从 25 支变为 50 支。已检查箭身、单支悬停和敌方汇总预览录像。录像和对比数据归档在 `artifacts/task-deliverables/arrow-hud-batched-rendering-20261124/`。

### 布置位置稳定性

旧布局按同组数量拟合整行间距，复制和移除飞矢都会触发重算。现在同一阵型的分区保持稳定，有效的旧槽位优先保留，新箭使用空隙或空行。可用空间放不下时，受影响分区沿用尽量少移动的有序压缩。倒计时、引导线、射出和悬停继续按每支飞矢处理。

同一隔离战斗中从手牌正常打出飞矢，再连续四次使用「星群」，对照两版分配给相同部署序号的坐标。移动统计以 0.1 画布单位为阈值。

| 步骤 | 原版移位数量 | 改后移位数量 |
| --- | ---: | ---: |
| 3 → 6 | 0 | 0 |
| 6 → 12 | 5 | 0 |
| 12 → 24 | 8 | 0 |
| 24 → 48 | 22 | 0 |
| 移除 1 支后剩余 47 支 | 13 | 0 |

新增的移除和复制布局断言、现有定向布局检查及 Beta C# 编译通过。验收录像 `stable-slots.mp4`、移动对照和分帧图存于同一归档目录。

后续允许局部微调。固定空位优先，空隙稍小才横移相邻飞矢。单支的微调上限是相对原槽位 8 个画布单位，先选移动支数更少的方案。定向检查确认一支飞矢挪动 4 个单位即可腾出所需间距，且后续插入不能把飞矢推过原槽位的微调上限。小幅调整仍不足以形成空位时，沿用有序压缩。布局检查及 Beta C# 编译通过。
